> Kelompok **Materialize** · Tahap program: rencana di proposal; uji saat hackathon, demo day, dan pendampingan · Masuk ke proposal: **Bag. 4 butir 4** (uji dan validasi pengguna dalam rencana kegiatan)
> Penanggung jawab utama: koordinator validasi pengguna, bersama koordinator teknis

**Tujuan:** menguji purwarupa dengan pengguna nyata untuk memvalidasi hipotesis, menemukan masalah, dan memperbaiki desain lewat iterasi.

---

## 1. Rencana uji

| Pertanyaan | Isian |
|---|---|
| **Siapa** — pengguna nyata yang sesuai persona | |
| **Apa** — yang diuji (kegunaan, fungsi, kinerja, stabilitas) | |
| **Di mana / kapan** — tatap muka/daring, lokasi mitra/lab/simulasi | |
| **Mengapa** — hipotesis yang divalidasi (dari [02-define.md](02-define.md)) | H1, H2, ... |
| **Bagaimana** — observasi, tugas terstruktur, pengukuran, wawancara setelah uji | |

Akses ke pengguna, data, dan fasilitas uji mitra memerlukan persetujuan mitra.

## 2. Jenis uji per jenis solusi

| Jenis solusi | Uji utama | Ukuran |
|---|---|---|
| Perangkat lunak | Uji kegunaan (*usability test*) dengan tugas nyata; uji fungsi | Tingkat keberhasilan tugas, waktu penyelesaian, kesalahan, kepuasan; metrik mitra (mis. waktu kirim notifikasi) |
| Formulasi (LKPI-01) | Homogenitas, organoleptik, stabilitas fisikokimia (pH, kejernihan, suhu), stabilitas dipercepat, efikasi antimikroba | Sesuai parameter standar mutu PT LKPI |
| Perangkat keras (LKPI-02) | Uji *repeatability* volume; uji pemakaian oleh petugas (evaluasi formatif) | Deviasi volume (< 5%), kebocoran, tumpahan, kemudahan pakai |

**Untuk alat kesehatan (LKPI-02):** pinjam konsep *evaluasi formatif* dari IEC 62366-1 — uji berulang selama pengembangan untuk menemukan kelemahan desain, dengan fokus pada **skenario penggunaan yang berisiko** (mis. cairan tumpah ke kulit, salah takar). Evaluasi sumatif penuh tidak diperlukan pada tahap hackathon.
